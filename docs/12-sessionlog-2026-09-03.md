# Sessionlog 2026-09-03 — Slutföra live LoRa-autentisering

> Vecka: 2 | Status: Genomförd och verifierad | Branch: `vibe/paw-line-corruption-fix-bf5bdb`

## Mål

Få en verkande live LoRa HMAC-SHA256 challenge-response mellan PLC (Pico 2 W)
och PAW (Feather RP2350 HSTX + Core1262 LoRa + 3-färg e-Paper), med gemensam
nyckel distribuerad till båda noder.

## Beslut (fastställda i sessionen)

- **Nyckeldistribution via USB-C-injektion** i stället för UART-trådning: värden
  skickar `K <32 hex>` över USB Serial till PLC och PAW. UNO Q:s USB är endast
  operatörsport; ingen UART utanför höljet. Medveten säkerhetskompromiss
  (nyckeln passerar USB-värden), accepterad för labb-skala.
- **Svarsformat utökat**: PAW svarar nu `0xB2 ‖ nonce ‖ HMAC` (49 B) så PLC
  verifierar mot exakt den challenge PAW svarade på.
- **En-utmaning-lås på PLC**: PLC slutar fritt omutmana var 5:e s; den håller en
  challenge tills svar eller 30 s timeout.
- **e-Paper-frysning**: visa AUTHENTICATING som ett engångs-splash, sedan håll
  det första AUTHENTICATED/FAILED-resultatet stilla (ingen cyklisk ommålning).

## Genomfört

### PLC (`plc-key-receiver.ino`)
- USB-nyckelinjektion (`receiveKeyOverUSB()` + `hexval()`), aktiv i `loop()`
  medan `!keyStored`.
- `initLoRa()` — initierar LoRa även när nyckel anländer via USB efter boot
  (tidigare bara om nyckel fanns vid boot).
- Nonce-eko i svar + verifiering mot ekad nonce.
- En-utmaning-lås via `awaitingResponse` + `CHALLENGE_RESPONSE_TIMEOUT`.

### PAW (`paw-main.ino`)
- Korrekt drivare för **3-färg B/W/R**-panelen (GDEH0154Z90, SSD1682):
  `GxEPD2_3C<GxEPD2_154_Z90c>` (B/W-drivaren lämnade ihållande röd bakgrund).
- e-Paper-pinnar korrigerade: `CS=5, DC=A0(26), RST=A1(27), BUSY=D25(25)`.
- Flicker-fix: `lastShownStatus`-dedup + `hasShownResult`-frysning — målar bara
  om vid verklig statusändring och håller resultatet stilla.
- USB-nyckelinjektion i `loop()` (robust, inte bara setup-fönstret).
- Borttagen död binär "Debug Serial"-hanterare.

### Script
- `scripts/inject_key.py` (ny): genererar/förhandsutfodrar 16-byte-nyckel,
  skickar `K <hex>` till PLC och PAW och verifierar matchande fingeravtryck
  (SHA256[:4]).

## Verifiering

Live LoRa (868 MHz, RSSI ~-68…-83 dBm):
```
[PRO-52] Response received from PAW over LoRa
[PRO-49] HMAC verification SUCCESS.
[PRO-52] Result sent to PAW: SUCCESS
[PRO-50] Authentication SUCCESS (LoRa)
```
Delad nyckel `21005399ef96232829976534533563e0`, fingeravtryck `8C376DF9` på
båda noder. Båda firmwares kompilerar rent och är flashade.

## Öppna risker / noteringar

- Nyckel över USB är en svagare förtroendegräns än UART (accepterad för labb).
- e-Paper gör fortfarande en ~14 s fullrefresh vid de ~2 uppstartsteckningarna;
  del av 3-färgspanelens fysik. Vid behov kan även dessa undertryckas.
- PAW: om nyckelinjektion missar boot och noden visar FAILED, kan nyckel ändå
  laddas via `loop()`-injektionen.
